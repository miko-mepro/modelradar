# 模型能力图谱（Model Atlas）

一个零依赖的静态网页，用来对比多个 AI 模型在知识、编码、推理、长上下文、工具自动化等维度上的实测成绩。页面提供能力雷达图、分项图、可调权重的综合排名表，以及逐项数据明细。

所有数据在构建时写入 JavaScript 文件，页面运行时不请求网络，也不需要安装依赖或打包。

## 使用方法

### 直接打开

用浏览器打开 `radar.html` 即可。双击文件或：

```bash
xdg-open radar.html
```

### 通过本地服务器打开（推荐）

```bash
cd modelradar
python3 -m http.server 8000
```

然后访问 <http://localhost:8000/radar.html>。

可选视图通过 URL 片段直接进入：

- `radar.html#overview`：总览（默认）
- `radar.html#backend`：后端与系统维度
- `radar.html#reasoning`：复杂推理与计算维度

维度 id 见 `radar-data.js` 中的 `dimensions`：`knowledge`、`backend`、`frontend`、`science`、`reasoning`、`professional`、`context`、`automation`。

## 界面操作

**左侧导航**：在总览与八个能力维度之间切换。点雷达图的轴标签也能进入对应维度。

**能力雷达（总览）**：每根轴是一个维度指数，50 表示参考平均水平。右侧勾选要对比的模型，搜索框和厂商下拉框同时作用于模型列表和数据表格。`默认对比` 恢复为 DeepSeek 与 GPT，另有 `全选` 与 `清空`。图例中的百分比表示该模型在实测、估计、证据不足三类证据上的权重占比。

**绝对分数 / 相对分数**：绝对刻度直接画指数；相对刻度把当前展示模型中的最高值缩放到 100，只改变图形比例，不改变表格数值。

**分项图（维度视图）**：只画原始实测。2 个评分项时用直角坐标，3 个及以上用分项雷达，只有 1 项时用竖柱状图；没有实测的评分项不占轴。

**模型数据总览表**：按当前视图的综合指数或维度指数降序排列。`仅有效实测覆盖 100%` 只保留当前权重下所有评分项都有实测的模型。维度表头可点击切换排序。

**用途优先级**：每个维度与每项评测都能在 0–3 之间调整（0 不纳入、1 一般、2 重要、3 核心），右侧同步显示实际占总分的百分比。`恢复默认分配` 回到数据文件里的 `defaultPriority`。默认侧重编码、推理、长文与工具工作流。至少一个维度必须大于 0，已纳入排名的维度至少要有一项参考有效的评测大于 0，否则页面给出提示。

**数据明细**：选择模型后可查看逐项原始实测、近邻估计、参考均值与总体标准差、权重、标准分、加权贡献、证据状态，以及遮挡验证误差和邻居校正过程。

**评分规则**：页面底部折叠区完整说明标准化、两层权重、近邻估计、遮挡验证、指数映射和数据接口约束。

## 数据维护

### 文件结构

| 文件 | 作用 |
| --- | --- |
| `radar.html` | 页面结构 |
| `radar.css` | 样式与响应式布局 |
| `radar-data.js` | 展示的模型与维度定义、实测成绩 |
| `radar-reference.js` | 冻结的参考模型与逐项参考成绩 |
| `radar-scoring.js` | 标准化、权重、近邻估计、遮挡验证 |
| `radar.js` | 路由、图表、表格、明细与交互 |

`radar-data.js` 只存实测，不存维度分和排名；维度分、综合分和雷达图都由 `radar-scoring.js` 现算。原始缺项不要补 0，直接不写该键；0 分是有效实测。

### 增加展示模型

在 `radar-data.js` 的 `models` 里追加一项：

```js
{
  id: "example",                    // 唯一
  name: "Example Model",
  detail: "max",                    // 配置档位等说明
  creator: "Example Labs",
  color: "#2563eb",                 // 六位十六进制
  url: "https://artificialanalysis.ai/models/example-model",
  intelligenceIndex: 50.0,          // 仅用于标准分完全相同时的排序
  breakdown: {
    backend: { terminalBench40: 50.0, livebenchCoding: 80.0 }
  }
}
```

只写有成绩的评分项。`breakdown` 的维度与键必须在 `dimensions` 中存在，数值须在 0–100 之间。

### 增加评测项或维度

1. 在 `dimensions[].items` 中增加 `key`、`label`、`metric`、`source`、`defaultPriority`。
2. 在 `radar-reference.js` 的 `items` 中增加同维度同 `key` 的记录，`label`、`metric`、`source` 必须与定义完全一致，`scores` 长度必须等于参考模型数量，缺测写 `null`。
3. 更新 `radar-reference.js` 的 `version` 与 `retrievedAt`，`sourceVersion` 与 `radar-data.js` 的 `version` 保持一致。

新增维度若暂时没有可用评测，`defaultPriority` 应设为 0。评测名称、来源或计分口径与冻结参考不一致时页面会直接报错，这是有意的约束，不提供静默兼容。

### 人类偏好榜的 Elo

写入 `breakdown` 前必须换算成对冻结参照的期望胜率，页面不接受原始 Elo：

```text
100 / (1 + 10^(-(elo - eloRef) / 400))
```

`eloRef` 按评分项单独取抓取时该榜全部上榜模型的 Elo 均值并随快照冻结，不随展示模型名单变化。当前参照值写在 `radar-data.js` 顶部注释里。

## 评分口径

- **参考准入**：每项至少 5 条有效参考且标准差大于 0。均值为 `μ = Σx / n`，总体标准差为 `σ = √(Σ(x − μ)² / n)`，标准分为 `z = (x − μ) / σ`。不满足的项移出计分，其余项统一归一权重。
- **两层权重**：维度权重 `W_d = p_d / Σp`，维度内分项权重 `v_dj = q_j / Σq`，分项占总分权重 `w_j = W_d × v_dj`。同一套权重用于所有模型，缺项不重新分配。
- **缺项处理**：只使用同维度内真实实测做比较项，选标准分距离最近的 3 个参考模型，以目标项邻居中位数为锚点，按岭回归（收缩系数 1）做局部校正。候选不足 5 个、预测越界或遮挡验证未通过时标记“证据不足”，按 `z = 0` 参与，明细里说明原因。
- **遮挡验证**：每次完整移除被验证模型重算参考，至少 5 个有效案例且校正估计的平均绝对误差严格小于均值基线才启用该规则。
- **指数**：维度标准分 `Z_md = Σ(v_dj × z_mj)`，综合标准分 `Z_m = Σ(W_d × Z_md)`，均通过 `S = 100 / (1 + exp(−Z))` 映射。50 表示参考平均水平，不代表正确率或胜率；综合分由维度标准分合成，不平均已映射的指数。
- **证据构成**：实测、估计、证据不足三类分别累加固定权重，合计 100%，只用于展示，不乘入能力分。

## 数据来源

- Artificial Analysis（AA）
- Epoch AI
- LiveBench
- LMArena
- Design Arena

页面“数据来源”区列出每个模型的来源链接。快照时间见页面右上角与 `radar-data.js` 的 `retrievedAt`。

## 浏览器要求

需要支持 ES2020 与 SVG 的现代浏览器。禁用 JavaScript 时只显示提示，无法查看图表和表格。
